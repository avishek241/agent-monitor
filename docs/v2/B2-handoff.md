# B2 handoff: runtime (dispatcher, adapters, supervision, merge queue)

Branch `v2-b2` (worktree `agent-monitor-b2`). Python 3.9+ standard library only. Spike results: `docs/v2/B2-spikes.md`.

## Spikes, in short
1. **Claude stream-json carries the handoff.** The final `result` line has `structured_output`. The raw schema must lose `$schema`/`$id` first, or Claude rejects it. Bonus: every run emits `rate_limit_event` with **absolute** `resetsAt` and utilisation. Limits are read from that event, never from "resets 8:50pm" text (M4).
2. **`codex exec resume`** accepts `--json --output-schema -o -c -m`, but **not `-s` or `-C`**. On resume the sandbox goes in through `-c sandbox_mode=…` and the working directory through the process cwd. `--output-schema` needs OpenAI strict mode: every key required, and optional keys made nullable (`schemas.for_codex`). Nulls are stripped from the result.
3. **Claude cross-account resume** works with `--resume <path>.jsonl`, not with the session id. Claude appends next to the given path, so the transcript is **copied into the run dir first**; later resumes reuse that copy.

## Open issues and decisions for W0
1. **Planner reasons are not stored on the task.** `stateReason` is not editable, so "waiting: domain X held by Y" lives in `dispatcher.notes` and `account_state.capacity.why`; the board still says "ready to run". Proposal: a B1 method `set_reason(id, text)` that does not bump `rev`. The dispatcher already calls it when it exists.
2. **`workspace.path`/`branch` are not stored** (not editable). B2 derives them from `worktreesDir/<id>` and `task/<id>`. Proposal: let DSP write `workspace` (views and the merge-queue UI would show the path).
3. **T26 deviation**: a busy main checkout keeps the task in `merging` and retries in 2 min. B1's T26 moves it to `review`, and leaving `review` then needs W0 to approve again. Recommendation: keep B2's behaviour, or let MQ take review→merging after T26.
4. B1's `merge_queue` table states (`active`, `waiting`) are not updated by B2. The queue is driven by the `merging` state. `done`/`failed` are set by T24/T25.
5. **Learned cost**: `GlobalStore` has no `usage_cost` API, so estimates stay at the defaults (S 8 %/30 min … XL 70 %/360 min). The dispatcher accepts `usage_cost.put()/recent()` as soon as B1 adds them.
6. Env naming: `DECK_ATTEMPT` is the attempt **number** (what `deck card` reads). The orphan marker is `DECK_RUN_ID=P:T:N`; the design called it `DECK_ATTEMPT`.
7. Interactive sessions are never marked hung. `deck hb --waiting` is only logged by B1, so B2 does no hang detection for `interactive`; it handles offer expiry only.
8. Not done: `import-v1 --watch` (one-shot only), event retention / `deck gc`, writing a v1-format card for S1 (§15), a Claude adapter smoke through deckd (the argv shape was verified in the spikes), and per-task `estimate` from `deck new --est-pct` (B1 field; honoured when set).
9. The project's `AGENTS.md`/rules must let workers run `deck` and read the brief. The real Codex smoke blocked because its rules said "no commands"; that was a property of the test setup, not a bug.
